## クオント研究の、未解決の2つの問題

バックテストを少しでも触ったことがあれば、たぶん両方に心当たりがあるはずです。

**問題1: 過学習があまりに簡単に起きる。** 多くのバックテストツールは、未知のデータに触れた瞬間に崩れる「年率40%」戦略を平気で見せてきます。サンプル内で（意識的にせよ無意識にせよ）最適化して、それで満足してしまうからです。これを検出するためにウォークフォワード検証があるのですが、手で組むのが面倒なので、たいてい飛ばされます。

**問題2: 既存のクオントツールは AI エージェントが操作できない。** Web UI 型のバックテストプラットフォームには CLI がありません。生の Python フレームワークは強力ですが API が広くステートフルで、Claude Code に「夜間に戦略を探して」と頼むと、エージェントは Python のトレースバックを解析し、何が壊れたか推測し、コードファイルをループで書き換える羽目になります。脆い上に、結局つきっきりで見ていないといけません。

[AlphaForge](https://alforgelabs.com) は、この両方を同時に解くために作りました。

## 「エージェントネイティブ」の実際の中身

多くのツールは `--json` フラグを後付けで足します。AlphaForge は最初から、**主たる利用者が人間でなく AI エージェントかもしれない**という前提で設計しています。

### 1. 機械可読なコマンドカタログ

```bash
alpha-forge system describe
```

全サブコマンド・引数・受理値・出力形状を JSON カタログとして吐き出します。エージェントはセッション開始時に1回これを呼べば、API 全体を即座に把握できます。ドキュメントを漁る必要も、フラグ名を当てるためのプロンプト工夫も不要です。

### 2. 構造化 JSON が全コマンドに

すべてのコマンドが `--json` を受け取り、安定したエンベロープを返します。

```bash
alpha-forge backtest run CL=F --strategy cl_momentum_v1 --json
```

未捕捉例外も構造化エラーエンベロープ（`error_code` / `message` / `suggested_fix`）で返るので、エージェントは人間向けテキストを解析せずに失敗を処理できます。各結果には `run_id` / `result_id` が付き、再実行なしに後段から参照できます。

### 3. MCP サーバ（alpha）

```bash
uvx alpha-forge-mcp
```

[alpha-forge-mcp](https://github.com/alforge-labs/alpha-forge-mcp) は CLI をラップする Apache-2.0 の MCP サーバです。Claude Code の `mcp_servers` 設定に追加すれば、AlphaForge のコマンドが MCP 互換エージェントの first-class ツールになります。

> 注: MCP サーバは alpha 段階です。安定インターフェースは CLI 本体で、MCP 層はこれから固めていきます。

### 4. 同梱のエージェントスキル

AlphaForge は Claude Code のスラッシュコマンドと Codex スキルを同梱しています。`explore-strategies` スキルが「アイデア → バックテスト → 最適化 → ウォークフォワード」のパイプラインを、使い捨てのチャット履歴ではなく**再利用可能・バージョン管理されたワークフロー**として体系化します。

### 5. 一晩の探索ループ

「何かが変わった」と感じたのはこの部分でした。魔法のような単発 `explore` コマンドがあるわけではありません。**ループを回すのはエージェント自身**で、同梱の `explore-strategies` スキルを使って CLI を駆動します。MCP サーバを動かした状態の Claude Code から、こう頼むだけです。

> 「エネルギー先物の戦略を一晩探索して。CL=F と WTI で MACD・RSI・ATR の各組み合わせをバックテストし、Sharpe > 0.8 のものはウォークフォワード検証して、結果をログに残して。」

エージェントは `system describe` のカタログを取得し、`--json` でバックテストと最適化を回し、構造化された結果を読み、負け筋を早期に枝刈りして、ランク付けされたサマリをディスクに書きます。朝起きると、目視すべきチャートの山ではなく、ショートリストができています。

## ウォークフォワード検証 — 誠実さの仕組み

アウトオブサンプル検証のないバックテストは、ひと手間多いだけのカーブフィッティングです。

AlphaForge ではウォークフォワード検証を `alpha-forge optimize walk-forward` で回します。インサンプル区間で学習し、アウトオブサンプル区間で検証し、戦略を有望とみなす前に OOS 窓の過半数が正であることを要求します。さらに `optimize sensitivity` があり、最適化済みパラメータを摂動させて、それがどれだけ脆い（過学習している）かを可視化します。

探索ループはこの WFT をフィルタに使います。インサンプルでは見栄えがするのに OOS で崩れる戦略は自動的に捨てられ、エージェントがその判断を肩代わりする必要はありません。

## 検証済みの結果を1つだけ（免責つき）

誤解を招かず具体的でありたいので、文脈つきで1つだけ実結果を挙げます。

ヘッジ付き3倍レバ NASDAQ-100 スリーブ（SMA200 + ATR サイジング）+ GLD + TLT を等加重で合算したバスケットの結果です。

- 合算の最大ドローダウン: 約10%（単体スリーブは 15〜40%）
- CAGR: 15.5%
- Sharpe: 1.20
- ウォークフォワード OOS 5窓すべて正

**免責（必読）:** 過去の結果は将来の成果を保証しません。これらの数値は約定スリッページ 0.05% を含み、価格リターンのみを用いています。これはバックテストであり、実取引ではありません。

戦略が「証明された」と主張したいのではありません。WFT で検証された分散が AlphaForge の出力形式でどう見えるかを示したかったのと、隠すこと自体がある種の不誠実だと感じたからです。

## アイデアから Pine v6 までのパイプライン

idea → TradingView Pine Script v6 までの全ワークフロー。各ステップが `--json` を話すので、エージェントが決定論的に連結できます。

```bash
# 1. CLI を記述（エージェントのオンボーディング）
alpha-forge system describe

# 2. JSON で定義した戦略をバックテスト
alpha-forge backtest run SPY --strategy spy_sma_rsi_v1 --json

# 3. Optuna TPE でパラメータ最適化
alpha-forge optimize run SPY --strategy spy_sma_rsi_v1 --json

# 4. ウォークフォワード検証（アウトオブサンプル）
alpha-forge optimize walk-forward SPY --strategy spy_sma_rsi_v1 --json

# 5. TradingView Pine Script v6 に出力
alpha-forge pine generate --strategy spy_sma_rsi_v1
```

各 `--json` 結果は `run_id` / `result_id` と `next_step` のヒントを持つので、エージェントは再実行なしに次に何を呼ぶべきか常に分かります。

## 試す

AlphaForge はパブリックベータです。無料トライアルはゲートなしで、ローカルでバックテストを回し、出力形式を見て、自分のワークフローに合うか判断できます。

- **無料トライアル + 価格**: [alforgelabs.com](https://alforgelabs.com) — 先着50名は Lifetime を $299（通常 $799）
- **MCP サーバ（Apache-2.0）**: `uvx alpha-forge-mcp`
- **OSS 兄弟**: alpha-visualizer（結果可視化）/ alpha-strike（発注実行）/ alpha-forge-mcp — すべて Apache-2.0

週末を手動のパラメータ調整に費やすより、エージェントに戦略候補を探させたい人向けに設計しています。当てはまるなら、この記事より無料トライアルのほうが速く適合を判断できるはずです。
